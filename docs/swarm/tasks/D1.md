# D1 data-schema (Stage 2)

Owner files: `src/world/data/**`, `tests/unit/world/data*.test.ts`. Grid.ts untouched.

## Design
- `bedstuy.json` gets `schemaVersion: 2` and an optional `faces` array: one entry per block face, keyed `street|side|from|to`
  (side = BlockFace.side, from/to = bounding cross streets, from = west/north end). `lots` are authored from -> to; the loader
  reverses for N and E faces so `lotsForFace` is ordered like `Lot.frontA -> frontB`.
- E/W faces (the short ones, on the avenues) include their corner lots. N/S faces list only the frontage between the corner
  buildings and are inset by the corner lots' `depthM` automatically.
- Missing fields get defaults (`resolveLot`); missing faces fall back to deterministic typology generators
  (`streetRow`, `avenueMixed`, `avenueRow`) seeded from grid.seed + face key. `pins` override single lots of a generated row.
- Validator (`validateFaces`, `validateLot`, `validateAgainstGrid`) returns path-qualified messages
  (`faces[3].lots[2].floors: ...`); `loadFaces` throws `SchemaError` listing all of them.
- Every explicit lot needs `widthM` (3-40) and `confidence`; floors 1-8 (0 only for vacant); unknown fields are errors.

## Data
- 40 faces, 840 lots. Generated once from the typology rows plus hand-placed anchors (POIs, R2 pass-2 notes), then frozen into
  the JSON as explicit lots (so a person can edit lot by lot from Street View checklists). All lots are confidence L unless
  an R2 source supports them (M). Antioch Baptist (828 Greene) is outside the grid per R2; not placed.

## Verification
- `npx vitest run tests/unit/world/data-schema.test.ts` (33 tests): validator negatives per rule, real file validates with 0
  errors, 40/40 faces covered, widths + insets == face length on all faces, determinism, defaults, v1 fixture loads.
